# Design-sync notes

## Repo shape

- Package shape (no Storybook). Build: `npm run build` (tsc declaration-only pass + vite library build). Entry: `dist/index.es.js`. CSS: `dist/style.css` (bundled from `src/styles.css`, which `@import`s tokens + all component CSS + the M PLUS 1p Google Fonts stylesheet).
- `vite.config.ts` sets `build.emptyOutDir: false` — without it, `vite build` wipes the `.d.ts` files the preceding `tsc --emitDeclarationOnly` pass just wrote (both steps write into `dist/`). If a future toolchain change reintroduces a clean-dist step, watch for this.
- `src/dev/` (the local demo app used to visually verify against a reference screenshot) is excluded from `tsconfig.json`'s `include` so it never leaks into the shipped `.d.ts` tree or the component count.
- All 59 exported components are real: 35 "product" components + 24 icon wrapper components (`src/icons/Icons.tsx`, thin wrappers around `@phosphor-icons/react`, MIT licensed). The icon wrappers keep the original hand-authored icon component names (`HomeIcon`, `PlaneIcon`, etc.) so nothing else in the codebase needed to change when the user asked to switch from hand-drawn SVGs to a real open-source icon set (iconshock.com surfaces Phosphor Icons; we depend on `@phosphor-icons/react` directly instead of scraping the aggregator site).
- `Logo` renders the real Gymcord logo (gymnast-silhouette-over-prismatic-gradient PNG), inlined as a base64 data URI in `src/assets/gymcordLogo.ts` — sourced from `gymcord-fantasy-web-app/assets/gymcord-logo.png` (the highest-res copy on disk, 500x500) and downsized to 96px/32px with `sips` before encoding. Never replace it with a placeholder/generated mark — always the real asset. The same source file is also `public/favicon.png` (dev) and `docs/favicon.png` (public showcase).
- `LoadingIndicator` auto-cycles to a new random phrase every 2s via `setInterval` unless a `phrase` prop pins it (used for a second, simultaneous indicator that shouldn't drift in sync with the first). No trailing "…" is appended by the component itself (an earlier version appended one; removed per explicit user request — the site-wide loading-phrase convention in memory still describes appending "…", which is now stale for this component specifically).
- `docs/` is a **separate public artifact**: a hand-built, live-rendering showcase page (not the design-sync `.review.html` tool, which stays internal/gitignored) for GitHub Pages, at `gymcorddiscord/gymcord-design-system` → `https://gymcorddiscord.github.io/gymcord-design-system/`. It vendors its own copy of `_ds_bundle.js`/`_ds_bundle.css`/`styles.css`/`_vendor/` (copied from `ds-bundle/` after every build — not symlinked) and mounts real components via `React.createElement` calls in a plain `<script>` (no JSX/build step). Has its own light/dark toggle for the page chrome only — component cards always render on a fixed dark background since the DS itself has no light mode. **Re-sync checklist**: after any component/token change meant to ship publicly, re-copy `ds-bundle/{_ds_bundle.js,_ds_bundle.css,styles.css,_vendor/*}` into `docs/`, and update the `mount(...)` calls in `docs/index.html` if props/exports changed.

## Known render warns

- None outstanding. `[GRID_OVERFLOW]` warns are resolved via `cfg.overrides`: wide full-width layout components (`AppHeader`, `AthleteTable`, `SegmentedToggle`, `LoggedOutHeader`, `DateTimePicker`) use `cardMode: "column"`; overlay components whose open state must render in-card (`FeedbackButton`, `Dialog`) use `cardMode: "single"` + `primaryStory`.
- `AppHeader`'s `AccountMenuOpen` story was tried and removed — `AppHeader` is pinned to `cardMode: "column"` for its Default/Preseason stories, and a component can only have one `cardMode` override, so the open-menu overlay got clipped rather than rendering. The account menu's interactivity is verified directly (headless-Chromium click dispatch + manual dev testing) instead of via a story.
- A component's grade can be invalidated by a **composed child's** source changing even when the parent file itself is untouched (e.g. `WeekNavigator` gaining `hideArrows` cleared `AppHeader`'s carried-forward grade on the next full capture). Don't assume "I didn't touch that file" means its grade is safe — always run a full `package-capture.mjs` pass (not just the components you edited) before treating the set as stable, and check for "need grading" lines you didn't expect.

## Design system facts worth remembering

- **Dark-theme only.** No light mode, no theme provider. Every component assumes a dark backdrop (`var(--bg-0)`/`var(--bg-1)`) — documented in `.design-sync/conventions.md`.
- **Red is reserved exclusively for long-term injury status** (`--injury-long-term`). Nothing else in the system — not generic errors, not destructive actions — uses red; `--danger` (orange) covers those. This is an explicit, deliberate brand rule from the user, not an oversight.
- Primary CTA pill buttons (`--radius-pill`) must be a **solid** fill, never a gradient — a past Gymcord site (the meet calendar) hit a visible rendering artifact on a gradient-filled large pill button. Small badge-sized pills (rank tiers, discipline tags) are fine with gradients/solid spectrum colors.
- Font is M PLUS 1p, loaded via a remote Google Fonts `@import` in `styles.css` (not shipped as local `.woff2` files) — this is intentional and matches every other Gymcord Fantasy site.

## Re-sync risks

- The whole component set (all 28) was authored and graded in one solo pass rather than fanned out to subagents — there is no wave/learnings history to fold on the next sync.
- `AppHeader`, `AthleteTable`, `SegmentedToggle`'s `NavigationTabs` export, and `FeedbackButton` were visually cross-checked against a real screenshot of the production Gymcord Fantasy lineups page during this session (not just graded in isolation). If the product's actual header/table design changes, these previews should be re-compared against a fresh screenshot, not just re-graded against themselves.
- `AthleteTable`'s authored preview uses only 3 rows; the real app renders 9+ rows (see the dev demo at `src/dev/App.tsx`, which mirrors the full reference screenshot with badge combinations not all present in the authored preview — home+bye, home+double-week, away+injury, etc.). If a future sync wants a richer table preview, `src/dev/App.tsx`'s `ROWS` array is the source to draw from.
- `@phosphor-icons/react` is a real runtime dependency (bundled into `_ds_bundle.js`, not external) — a future icon addition should use the same package rather than reintroducing hand-drawn SVGs.
- No Storybook exists in this repo and none is planned — if one is added later, re-run detection (delete the `"shape"` pin from `.design-sync/config.json` first) rather than assuming package-shape forever.
- `Dropdown` has a `defaultOpen` prop specifically so its "Open" preview story is real composition (`<Dropdown defaultOpen .../>`) rather than hand-rolled markup imitating the open state — don't reach for a lookalike when a small real prop addition solves it instead.
- Mid-session, the local Vite dev preview (`localhost:5180`, unrelated to the shipped bundle) intermittently showed "Invalid hook call" console warnings and unreliable plain `.click()` dispatch, after many rapid preview_stop/start + HMR cycles and dozens of edits in one sitting. Confirmed benign every time it recurred: the real compiled bundle always rendered N/N clean in actual headless Chromium via `package-validate.mjs`, and a full `mousedown`+`mouseup`+`click` event dispatch (not a bare `.click()`) reliably worked. Treat this dev-preview tool flakiness as expected background noise in a long session — verify via the headless-Chromium pipeline and a full event dispatch before concluding a component is actually broken.
- `Dialog` and the feedback flow: `FeedbackButton` was refactored from one-off modal markup to `Dialog` + `TextField multiline` — if the feedback flow needs to change again, prefer extending `Dialog`'s generic slots (`title`/`children`/`actions`) over adding feedback-specific markup back into `FeedbackButton`.
- Icon additions this session all follow the same pattern: import the raw Phosphor icon in `src/icons/Icons.tsx`, wrap it in a `*Icon` function defaulting to `weight="bold"` (brand marks like Discord/Moon/Sun use `weight="fill"` instead — they read as solid marks, not outlines), export it, then use it. Keep doing this rather than importing raw Phosphor components directly into other component files.
- `TextField`'s `multiline` mode forces the label to its floated (top) position always, regardless of focus/value — centering a label in a variable-height textarea doesn't make sense the way it does for a single-line input. Don't "fix" this to match the single-line behavior.
- `LeagueSwitcher` was rewritten from a static `teamName`/`leagueName` display into a real multi-league dropdown: it now takes `leagues: LeagueOption[]` (`{ id, teamName, leagueName, icon }`), `activeLeagueId`, `onChange`, and `defaultOpen` (for demos). The trigger shows the active league's icon + names; the menu (reusing `.gds-dropdown__menu`/`.gds-dropdown__item`) lists every other league, each with its own icon, and closes on outside click/Escape/selection — same interaction pattern as `Dropdown`. `AppHeader` passes `leagues`/`activeLeagueId`/`onLeagueChange` straight through and only renders the switcher when both `leagues` and `activeLeagueId` are present.
- Ten themed leagues were added as icons to give the multi-league demo real variety: `StarIcon`, `GoatIcon`, `UnicornIcon`, `FlowerIcon`, `BooksIcon`, `PaletteIcon`, `MedalIcon`, `ButterflyIcon` (plus the existing `SunIcon`/`TrophyIcon`). Phosphor Icons has no literal goat or unicorn glyph — `GoatIcon` wraps `Horse` (nearest hooved-mascot substitute) and `UnicornIcon` wraps `Sparkle` (same whimsical/magical mascot feel), both noted inline in `src/icons/Icons.tsx`. Follow the same "find the nearest semantic Phosphor glyph" approach for any future mascot-style icon that doesn't exist literally in the set.
- `AppHeader` gained a third `phase`: `"standard"` (alongside `"season"`/`"preseason"`) — a bare header with just `<Logo />` and, if `theme` is passed, the `ThemeToggle`. No league switcher, week navigator, or nav tabs. For pages with no league/week/tab context (e.g. a host setup or rules page that still wants the app shell chrome). Styled via `.gds-app-header--standard { justify-content: space-between }` in `AppHeader.css`.
- The formal design-sync grading/capture pipeline (`package-capture.mjs`/`package-validate.mjs`, referenced above) was not available as an invokable tool in the session that added the above — no `resync.mjs` or equivalent driver script exists as a checked-in file in this repo; that tooling is provided externally when the `/design-sync` skill runs. In its absence, the bundle shipped to `docs/` was rebuilt manually with a one-off `vite build` (iife format, `classic` JSX runtime to match the existing bundle's `React.createElement` style, external `react`/`react-dom` mapped to the `_vendor/react.js` globals) and verified by loading `docs/index.html` against that bundle in a real browser rather than via the internal grader. If the real pipeline becomes available again, run a full unscoped capture pass before trusting any carried-forward grade — this session did not update `.design-sync/.cache/review/*.grade.json` for `LeagueSwitcher`/`AppHeader`.
- `.gds-app-header` needs `width: 100%` (+ `box-sizing: border-box`, since it has horizontal padding) — without it, the header shrinks to its content width instead of filling its container. This was invisible in `src/dev/App.tsx` (a plain block-level parent) but broke visibly in the showcase page, whose `.card .card-body` wrapper is `display: flex` (sized for small side-by-side demo elements, not full-width components) — a header with few children (the `standard` phase, or `LoggedOutHeader`) would clump on the left instead of spanning the card, pushing the theme toggle / Log in / Sign Up away from the right edge. `AthleteTable` already sets its own `width: 100%` for the same reason — any component meant to span its container should do this itself rather than relying on the parent to stretch it.
